# TikTok Native Buffer 0.3.0

保留 TikTok 网页原生播放器，在插件内选择画质，并为当前和后续视频准备同一版本的共享缓存。最高并发 **8**，默认自动。

## 0.3.0：自由选择视频画质

- 面板顶部的“视频画质”可选：最高画质、1080P、720P、540P、480P、360P、原生自动。
- 页面提供其他可播放档位时会加入选项，例如 1440P、960P 或 240P；下方另列本条实际提供的画质。
- 默认仍为最高画质。选择会保存，并应用到当前视频与后续预缓存；旧版“原生自动”设置会保留。
- 指定档位不存在时，选择不高于该档位的最高可用版本；全部版本都更高时，使用最低可用版本。面板说明实际采用的画质，所选偏好不被覆盖。
- 切换会取消旧预取计划，并通过原生切换流程更新播放版本；原有缓存按资源地址隔离，仍受总容量限制。切换可能短暂重新加载。
- “原生自动”交由 TikTok 选择，未来视频仍需等它选定版本后才能开始对应预缓存。

本次完成源码修改和构建，未运行测试或进行网页实测；目录中的 35 项测试结果与截图属于 0.2.0。

## 0.2.0：固定最高画质

- 默认开启“固定最高画质”。每条视频从页面已提供的版本中选择浏览器支持的最高分辨率；只有 720P 的视频仍选 720P。
- 通过原播放器的初始化接口约束版本，使用同一版本提前缓存后续视频，保留原视频元素和控件。
- 不再等到原生播放器选中后，才开始准备第二、第三条视频。页面仍需先提供这些视频的元数据和有效地址。
- 面板显示“已固定 1080P”、各条目标画质、缓存进度，以及本页并发峰值和成功完成的分块数。
- 已存在的较低版本可能经原生流程重新加载一次，保留位置、暂停状态、音量和播放速度。
- 可在“画质策略”切回“原生自动”。观察到媒体错误时，对该视频解除固定并交回原生选择，避免反复切换。

“最高”按已提供的分辨率、帧率和编码信息选择；同条件优先可播放的 HEVC，再比较码率，不是对视觉质量作主观评测。不会伪造平台未提供的 4K 或原片。

## 安装

已安装 Tampermonkey：[点击安装 / 更新 TikTok Native Buffer](https://raw.githubusercontent.com/mpftc/tiktok-native-buffer/main/TikTok-Native-Buffer.user.js)。安装或更新后刷新 TikTok 网页。

手动安装：

1. 打开已安装的 Tampermonkey，选择“添加新脚本”。
2. 用同目录 **TikTok-Native-Buffer.user.js** 的完整内容替换编辑器中的模板，保存。
3. 刷新 TikTok 网页。右下角出现“缓冲”按钮，点击展开设置。
4. 面板出现“下载接管已生效”才表示实际媒体请求经过脚本。仅出现面板不代表已接管。

更新现有安装：使用上方安装链接，或用新版 .user.js 全文替换旧脚本，保存后刷新 TikTok。扩展需要自身正常的用户脚本执行权限。脚本要求在页面主世界、document-start 执行，元信息已设置 `@grant none`、`@sandbox raw` 和 `@run-at document-start`。

停用：面板“暂停接管”让新请求使用原生下载，已开始的流继续完成。彻底停用可在 Tampermonkey 禁用脚本后刷新页面。清理闲置缓存不会清除浏览器原生视频缓冲。刷新或关闭标签页清空脚本媒体缓存。

## 设置

| 设置 | 默认 | 可选 |
|---|---:|---|
| 视频画质 | 最高画质 | 最高 / 1080P / 720P / 540P / 480P / 360P / 本条其他档位 / 原生自动 |
| 缓冲容量 | 256 MiB | 64 / 128 / 256 / 512 MiB |
| 当前向前准备 | 60 秒 | 15 / 30 / 60 / 120 秒 |
| 后续视频数量 | 3 条 | 0–5 条，不含当前与回看 |
| 每条准备开头 | 10 秒 | 5 / 10 / 15 / 30 秒 |
| 每条后续字节上限 | 8 MiB | 2 / 4 / 8 / 16 MiB，音视频合计 |
| 回看保留数量 | 1 条 | 0–2 条 |
| 最高并发 | 自动，初始 2 | 自动 / 1 / 2 / 4 / 6 / 8 |

若要手动最高档，设“最高并发”为 **8**。音频、视频、多个原生请求和脚本预取共用这 8 个额度。此限额只覆盖脚本管理的子请求，原生回退、未适配请求及其他标签页另计。降低上限后，已开始的必要请求完成，新任务按新额度启动。

容量包括已保留媒体字节、在途工作空间和脚本持有的交付副本；浏览器网络栈、解码帧、原生媒体缓冲和对象开销另计。降低容量时，正在交付的固定数据先完成，随后收回；不能把数值解释为浏览器进程内存上限。

设置保存在 TikTok 站点的本地存储，刷新后沿用；其他已打开标签页不会自动同步本次更改。预算、缓存和并发实际按单个标签页管理。脚本没有统计上报、外部配置服务或第三方依赖。

## 面板读数

- **播放器已缓冲**：原视频元素 `buffered` 中，从当前时间连续可播放的秒数。
- **连续可用覆盖**：原生缓冲与经索引核对的脚本缓存共同覆盖的连续时间。不会直接改变原生进度条。
- **后续准备就绪**：原生已有足够缓冲，或当前已确认画质的初始化数据、音视频目标范围均已准备。
- **等待播放器就绪**：尚未识别可控制画质的原生播放器。
- **等待可用视频地址**：当前这条尚未提供能识别、能缓存的视频版本，可能是非视频内容。
- **尚未预缓存 · 等待原生版本**：仅在原生自动模式下，尚未确认其选择时出现。
- **按字节准备 · 时长未知**：没有支持的时间索引，按每条字节上限准备。完整文件已缓存时可计为该条全部就绪；未完整时不估算秒数。

60 秒、后 3 条等是准备目标，受索引、带宽、页面已提供的资源、原生画质选择、签名有效期与容量限制。片段边界或既有缓存可使可用覆盖超过目标。

## 已实现

- 开放尾部和有限 Range 的流式响应，正确的 206 与 Content-Range；严格按原字节顺序输出至 EOF。
- 有限子请求校验，重叠区间复用，进行中任务去重；消费者单独取消，最后一个消费者取消时中止任务。
- 保留媒体请求凭据、来源设置及 TikTok 的原播放器、原来源和缓冲写入过程。
- 全页共享调度，前台需求抢占非必要预取；后台、暂停播放和快速滑动时暂停相应预取。
- SIDX v0/v1 直接引用解析、关键帧回溯、基本编辑列表偏移处理；分离音视频取时间覆盖交集。
- 不同完整签名 URL 隔离。出现可检测的总长度或验证器冲突时停止复用该资源，交回原生。
- 响应建立前失败可回退原请求；流中失败只对尚未交付的子请求有限重试，仍失败则向原播放器报告流错误，由其恢复。

## 首版边界

- 验证对象是 Chrome 当前 TikTok 推荐流。其他地区、页面类型、账户实验和播放器版本可能不同。
- 不接管 XHR、Worker 内部下载、浏览器直接读取媒体来源、直播或图片轮播；没有适配器时保留原行为。
- 原生只需普通流读取器的样本已经实测；BYOB 读取器未实现。
- 普通无 SIDX 的 MP4 不解析完整样本表；后续视频会准备文件开头，最多达到单条字节上限，文件足够小时可完整缓存。嵌套 SIDX、复杂编辑列表及异常时间索引同样退化。
- 设置 3 条不保证立刻准备完 3 条：仍受页面是否提供地址、下载速度及容量限制。固定最高模式会立即选择目标版本；原生自动模式仍需等待其版本选择。
- 画质固定使用当前 `NEW_TT` 播放器的内部初始化与切换接口，通过有限、带结构检查的 React 组件引用定位。TikTok 更新内部实现后可能需要适配；接口缺失会显示等待状态。
- 自动并发是初步启发式，依据吞吐、排队与错误退让；尚未做同视频、同网络的 1/2/4/8 并发提速对照。
- 采用按需预留的单一预算，没有固定占住 32 MiB 工作区，也没有硬分割 60%/30%/10% 的视频配额；通过优先级淘汰共享容量。

## 源码与开发

纯 JavaScript，无需安装依赖。Node.js 20 或更高版本：

```text
node build.cjs
node --test test/core.test.cjs test/quality.test.cjs
```

| 文件 | 职责 |
|---|---|
| src/range-engine.cjs | 调度、区间缓存、内存预留、有限范围下载 |
| src/fetch-transport.cjs | 原 Fetch 包装、流式响应与取消 |
| src/media-index.cjs | MP4/SIDX 索引与可用时间 |
| src/page-adapter.cjs | 推荐数据、视频识别、预取计划 |
| src/quality-policy.cjs | 画质档位选择与原生播放器初始化适配 |
| src/panel.cjs | 缓冲面板与设置 |
| src/entry.cjs | 启动、设置存储、停止 |
| test/core.test.cjs | 可重复协议与缓存测试 |

只读诊断：页面主世界中的 `window.__TikTokNativeBuffer.getStatus()` 返回不含媒体地址的状态；`getSettings()` 返回配置。

实现参考了 [Bilibili-thread-ripper](https://github.com/MrTangLuyao/Bilibili-thread-ripper) 的 Range 下载思路；本项目代码独立编写，以 MIT 许可提供。

验证细节见 [VALIDATION.md](./VALIDATION.md)。
